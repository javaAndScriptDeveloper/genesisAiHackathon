# AI-аналіз фото прогресу — план реалізації

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox syntax.

**Goal:** Кнопка «Analyze progress» у Check-ins: за згодою надсилає 2 фото + контекст прогресу на сервер → Gemini → структурований текстовий опис змін; фото ніде не зберігаються на сервері.
**Spec:** `docs/superpowers/specs/2026-11-21-photo-progress-ai-design.md` (підхід A; HTTP для демо з чесним текстом у згоді).
**Tech:** Next.js route handler (server-only), `@google/genai` через `lib/ai/gemini.ts`, zod, Vitest, bun.

## Global Constraints
- Фото не логуються й не пишуться на диск/БД на сервері; у `FitState` зберігається лише текст результату й дати фото.
- Лише `image/jpeg|png|webp`, рівно 2 фото, кожне ≤ 400 КБ після base64-декодування; дата `before` < `after`.
- Ліміт 5 аналізів на день на `progressToken` (in-memory Map у route).
- Відповідь моделі — тільки через `responseSchema` + zod: `{ suitable: boolean; summary: string; observations: { area: string; text: string }[] (≤4); encouragement: string }`.
- Системна інструкція: нейтральна мова; без оцінок тіла, без «ідеалу», без чисел з фото (вага/% жиру), без медичних висновків; якщо фото не про тіло або неякісні → `suitable:false` з поясненням; мова відповіді = `locale`.
- Без ключа → 503 `{error:"ai_unavailable"}`; UI показує «Analysis is unavailable right now».
- Копірайт англійською в `messages/parts/progress.json` (+ build-messages); uk.json не чіпати.
- Premium: перший аналіз безкоштовний, далі `PremiumGate` (prop-прапорець, рішення продукту).
- Комміт-трейлер: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
