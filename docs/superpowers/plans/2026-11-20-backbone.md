# Hackathon Backbone Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Commit to `main` -> tests -> images built -> live on the Hetzner VPS; `http://37.27.8.181/api/health` answers with a DB-backed response.

**Architecture:** Monorepo, two services (`frontend`, `platform-backend`) + Postgres, run by docker compose. CI builds images to GHCR and deploys over SSH (`compose pull && up -d`), then curls the VPS to verify.

**Tech Stack:** Node 22, TypeScript, Fastify, `pg`, Vitest, `@testcontainers/postgresql`, Next.js (App Router, standalone), Docker Compose, GitHub Actions, GHCR.

**Spec:** `docs/superpowers/specs/2026-11-20-backbone-design.md`

## Global Constraints

- VPS: `37.27.8.181`, user `root`, key `ssh/hetzner_ed25519` (private key only in GitHub secret `VPS_SSH_KEY`, never committed).
- Services named exactly `frontend` and `platform-backend`; Postgres service `db`.
- Route: `GET /api/health` -> `{"status":"ok","db":true}`; runs `SELECT 1`; no tables.
- Public: only `frontend` on port 80. `platform-backend` and `db` not published.
- CI: tests + build + push + deploy + verify. No scanners, lint gates, releases, replicas, Watchtower.
- GHCR image names must be lowercase (repo owner has capitals).
- Commit trailer per `CLAUDE.md`: `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.

## Review Focus

- DB down/unreachable: `/api/health` returns 503 `{"status":"error","db":false}`, process stays alive.
- Missing `DATABASE_URL` at boot: fail fast with a clear message.
- Frontend while backend is down: page renders an error state, not a 500.
- Deploy with a stale/failed pull: CI step must fail (non-zero), not report green.
- Verify step must wait for startup (retry), not fail on first connection refused.

**Interfaces:**
- Consumes: repo secrets `VPS_SSH_KEY`, `POSTGRES_PASSWORD`; built-in `GITHUB_TOKEN`.
- Produces: on push to `main`: job `test` -> job `deploy`. PRs run `test` only.

- [ ] **Step 1: Job `test`** (`ubuntu-latest`): checkout, setup-node 22 with npm cache, `npm ci && npm test` in `platform-backend`, `npm ci && npm run build` in `frontend`.
- [ ] **Step 2: Job `deploy`** (`needs: test`, only `refs/heads/main`, `permissions: packages: write, contents: read`, `concurrency` group so deploys don't overlap): compute lowercase `IMAGE_PREFIX`; `docker/login-action` to ghcr; `docker/build-push-action` for each service tagged `:sha-<sha>` and `:latest` with GHA cache.
